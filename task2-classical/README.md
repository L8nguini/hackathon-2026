# The Classical Pipeline Strikes Back

### The bright idea

Can we generate useful game descriptions without LLMs? Traditional NLG uses a modular pipeline to turn structured data into text. Participants can build their own pipeline, from selecting relevant facts (content planning) and organizing them (document planning) to choosing wording (microplanning) and generating sentences (realization). For example, a description could highlight Linux compatibility and affordability for a budget Linux gamer, or VR support and demanding system requirements for a hardcore VR enthusiast. Participants can experiment with templates, rules, grammars, and different ways of selecting and presenting information to create descriptions that are both useful and personalized.

### The goal

Explore the fundamentals of classical NLG and generate game descriptions that are both readable (and personalized) while remaining faithful to the data.

### Data to use

- Kaggle Steam Dataset 2025. Useful properties may include game name and description, price, release date, genres, tags, playtime, supported platforms, system requirements, and review sentiment. You don't need to use every property.
- Participants can define their own player profiles to guide content selection.

### Evaluation
If the Tinder app is ready, the outputs could be evaluated there.
